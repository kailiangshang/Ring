Ring 功能联动设计

以用户实际工作流为线索，重新审视布局和交互

核心工作流

Ring 的主循环：对话 → 归档 → 图谱生长
1. 对话产生内容 → 2. AI 建议归档 → 3. 用户确认节点位置 → 4. 生成 MD + 更新图谱 → 5. Git commit / PR
设计关键：这个循环必须在同一个界面内完成
如果用户需要从 Chat 切到 Graph 再切到 PR 才能完成一次归档，流程就断了

当前问题分析

Chat / Graph / PR 完全隔离
当前 Tab 切换导致视图互斥。用户在 Chat 中看到归档建议时，看不到图谱结构，无法判断 AI 建议的节点位置是否合理
图谱树只在 Graph 视图可见
PRD 核心是"知识图谱为骨架"，但骨架在大部分时间（Chat/PR/Sessions）是隐藏的。用户失去空间感
归档建议的回调是空的
ArchiveSuggestion 的 on_accept/on_dismiss 是 () => {}，归档流程没有 UI 闭环
通知没有入口
PRD 有完整通知系统（PR 状态、成员变更、Session 邀请），但前端没有通知 UI 组件
顶层导航结构低效
当前 NavBar + RingNavBar 占两条 bar，在 Ring 工作区内，返回 Hub 和全局导航不应该是最高优先级的视觉元素
Graph 视图和 Ring 视图脱离 Layout
GraphView 用 height:100vh 脱离了 Layout 的 flex 容器，破坏了一致性

联动设计要点

左栏图谱树始终可见
不管在 Chat/Graph/PR 哪个模式，左侧图谱树都在。用户始终知道自己在哪里。归档建议时，AI 推荐的节点在树中高亮。
右栏按需弹出，不占常驻空间
点击树中节点、AI 归档建议触发、PR 查看 diff 时弹出。默认隐藏，把空间让给主内容区。
导航合并到左栏底部
Chat/Graph/PR/Members/Sessions 不再用顶部 Tab，而是放在左栏图谱树下方的图标列表中。节省一条导航栏的高度，且和图谱树形成统一的侧栏。
通知 → PR 联动
顶栏铃铛图标显示未读数。新 PR 通知点击直接跳转到 PR Detail。成员加入通知跳转到 Members。Session 邀请跳转到 Sessions。
Graph 全屏模式 — 从侧栏进入
选择 Graph 模式时，D3 力导向图占据中栏全宽。左栏的树仍然保留作为导航。右栏可选显示节点详情。不是 100vh 脱离布局，而是嵌在三栏内。
Auto 模式状态清晰可见
Chat 顶栏显示 Auto 状态标签。Auto 模式下归档不弹确认框，但仍显示 toast 通知："已归档到 节点X"。用户可随时切换回手动模式。
