# Ring 用户流程

## 1. Ring 生命周期

```
创建 Ring → 蓝图构建 → 日常使用 → 持续演化
```

### 1.1 创建 Ring

1. 用户在 Ring Hub 点击"创建 Ring"
2. 填写 Ring 名称（如"产品竞品分析组"）
3. 填写 AI 角色描述（如"你是一个产品分析专家，帮助团队进行竞品研究"）→ 初始化 `.ring/role.md`
4. 关联 GitLab 仓库：
   - 输入已有仓库地址，或
   - 点击"自动创建"（可选填 `namespace`，默认用个人 namespace）
5. 凭证复用全局 GitLab 配置（Setup 时已配置）
6. 后端初始化仓库 → push 初始 commit
7. 进入蓝图构建阶段

### 1.2 蓝图构建

**入口页面展示模板卡片列表**，用户可以选择：

**快速路径**：
1. 用户浏览预设模板（产品研究、项目管理、学习笔记、技术文档、空白）
2. 点击模板卡片 → **预览图谱结构**（节点+边 D3.js 可视化）
3. 点击"使用此模板" → 确认蓝图 → 建立 → 进入 Ring 空间

**深度路径**：
1. 用户点击"自定义"或"从零开始"
2. Group Ring 使用蓝图 prompt + role.md 叠加作为 system prompt，引导构建
3. 通过不限轮数的对话，和用户反复确认：
   - 需要几个图谱（默认上限 3，过高提醒资源消耗）
   - 每个图谱的主题和顶层分类
   - 初始节点结构
4. 每次调整后展示可视化预览
5. 用户点击"确认蓝图" → 建立
6. 进入 Ring 空间，开始日常使用

### 1.3 日常使用

Ring 进入持续演化阶段，成员在三种模式间切换使用。

## 2. 三种使用模式流程

### 2.1 日常对话模式（默认）

**触发**：进入 Ring 后默认状态

**流程**：
```
用户提问/聊天
  → Group Ring 响应（查询图谱、归档内容，回答问题）
  → 不产生任何 Git 操作
  → 对话内容仅存在于会话中
```

**Export 能力**：
- 用户可在对话中随时点击 export 按钮
- 将当前对话片段标记为"值得归档"
- 触发手动归档流程

### 2.2 手动归档模式

**触发**：
- 用户在对话中说"归档"/"保存"/"记录到图谱"
- 用户点击 export 按钮
- Group Ring 主动推荐"是否归档到图谱"（工具产出后）

**流程**：
```
标记归档
  → 后端自动 git pull（确保本地图谱最新）
  → Group Ring 分析内容，识别关键信息
  → Group Ring 推荐图谱操作（"我建议创建新节点 XX" 或 "挂载到节点 YY 下"）
  → 展示推荐预览
  → 用户确认
  → 生成 Markdown 文件 + 更新 graph.json
  → 创建者/管理员：直接 commit + push
  → 成员：创建分支 → commit → push → GitLab API 创建 MR → 进入审核队列
  → 所有成员自动 pull 最新内容
```

**PR 审核队列**：
```
成员提交归档 PR
  → 进入审核队列（前端显示队列位置）
  → 创建者逐个审核（串行，避免 graph.json 冲突）
  → 无冲突：合并 → 所有成员 pull
  → 有冲突：打回（关闭 MR + 通知成员）
  → 成员收到打回通知 → pull 最新 → 重新提交
```

### 2.3 Auto 模式

**触发**：用户点击"Auto"按钮

**流程**：
```
用户上传文档 / 对话 / 使用工具
  → AI 自动判断内容是否值得归档（基于 LLM 语义判断：内容包含决策/结论/知识点）
  → AI 自动执行归档（创建/更新节点，生成 Markdown，commit）
  → 不需要用户逐个确认
  → 用户可随时退出 Auto 模式
```

**边界**：
- 闲聊内容不归档（"今天天气真好"）
- 上传文件自动归档
- 对话基于语义判断是否归档
- 误归档可通过多种方式修正（图谱编辑、对话修正、Git 回滚）

## 3. 成员加入流程

### 3.1 开放链接加入

```
创建者生成开放链接
  → http://{创建者内网IP}:7420/join?token=xxx
  → 被邀请人点击链接
  → 创建者的 ring-server 服务安装导航页（去中心化）：
     ├── 页面显示：Ring 名称 + 描述 + 成员数
     ├── 自动检测访问者 OS（User-Agent）
     │   ├── Windows → 高亮 Windows 下载按钮
     │   ├── Linux/WSL → 高亮 Linux 下载按钮
     │   └── macOS → 高亮 macOS 下载按钮
     ├── 下载链接指向 GitHub Releases：
     │   https://github.com/{owner}/ring/releases/latest/download/{filename}
     ├── 已安装 Ring 的用户：直接点击"继续加入"
     └── 未安装用户：三步引导
         1. 下载对应平台二进制文件
         2. 解压并运行 ring-server
         3. 点击"继续加入"按钮
  → "继续加入"跳转 http://localhost:7420/join?token=xxx&creator_ip={创建者IP}
  → 本地后端处理：
     ├── 未 Setup → 先走 Setup 向导 → 完成后自动 join
     └── 已 Setup → 直接走 join 流程
  → 输入 display_name
  → Ring 自动从 GitLab clone 仓库到本地
  → 分配 token_id（自增长）
  → 加载图谱和归档内容
  → 同步其他成员名称列表
  → 加入 Ring，获得对应角色权限
```

> **去中心化安装**：安装导航页由分享链接的用户 ring-server 提供，无需中央安装服务器。二进制文件统一从 GitHub Releases 下载。

### 3.2 审核链接加入

```
创建者生成审核链接
  → 被邀请人点击链接 → 创建者的 ring-server 服务安装导航页（同 3.1）
  → 安装并"继续加入"后看到 Ring 名称 + 成员列表
  → 输入 display_name + 申请理由
  → 创建者收到通知："xxx 请求加入 Ring"
  → 创建者看到申请人名字 + 现有成员列表
  → 批准 / 拒绝
  → 批准后：分配 token_id，自动 clone 仓库，通知申请人
  → 拒绝后：通知申请人（附理由）
```

## 4. PR 审核流程（创建者视角）

```
成员在对话中标记归档
  → 后端自动：创建本地分支 → 生成 Markdown + 更新 graph.json → commit → push
  → 后端通过 GitLab API 创建 MR
  → 创建者在 Ring 归档视图看到 PR 通知
  → 创建者点击"查看 Diff" → 弹出并排对比视图
  → 创建者点击"合并" → GitLab API 合并 MR → 所有成员自动 pull
  → 或创建者点击"拒绝" → GitLab API 关闭 MR
```

## 5. 图谱生长流程

### 5.1 新内容产生

```
用户在对话中讨论新主题 / 上传新文件 / 使用工具
  → AI 分析内容
  → 匹配蓝图中某个图谱的某个大类
  → 建议：
    a) 归入已有子节点
    b) 在已有大类下创建新子节点
    c) 建议新增顶层大类（需用户确认，因为这改变了蓝图结构）
```

### 5.2 节点创建

```
AI 建议"创建新节点 XX"
  → 用户确认（手动模式）/ AI 自动执行（Auto 模式）
  → 生成节点数据（graph.json 更新）
  → 生成对应的 Markdown 文件
  → Git 操作（commit 或 PR）
```

### 5.3 边创建

```
Group Ring 识别两个节点之间的关系
  → 建议"节点 A 和节点 B 存在'依赖'关系"
  → 用户确认 / AI 自动执行
  → 更新 graph.json
  → Git 操作
```

## 6. Session 多人讨论流程

### 6.1 创建 Session

```
Session 创建者（需有 Ring 内的 Session 创建权限）
  → 检查：该 Ring 是否已有活跃 Session（一次只能有一个）
  → 在 Ring 空间点击"新建讨论"
  → 选择预设场景（必选）：
     ├── discussion（自由讨论）：多人自由聊天，基础讨论助手
     ├── deep_research（深度调研）：跨源聚合 + 报告生成
     ├── meeting_archive（会议归档）：结构化提取 + 归档推荐
     └── learning_center（学习中心）：知识解读 + 概念提取
  → 填写 Session 标题（如"竞品 A 深度讨论"）
  → 选择是否开启归档（可后续动态切换）
  → 选择邀请哪些 Ring 成员
  → 系统创建 Session Ring（基于预设场景配置）
  → 创建者成为 session owner
  → 被邀请成员收到 WebSocket 通知
```

> 预设场景决定 Session Ring 的行为和能力边界。例如选择"深度调研"时，Session Ring 会主动调用搜索、爬取、聚合等工具。

### 6.2 Session 内讨论

```
成员发消息
  → 消息发送到创建者后端（WebSocket）
  → 创建者后端存入 session_messages（带 seq_num）
  → 广播给所有 session 成员（包括发送者）
  → Group Ring（共享实例）响应
  → AI 回复也广播给所有成员
```

**特点**：
- 所有成员共享一个 Group Ring 实例
- AI 回复对所有人可见
- 消息通过创建者后端中转
- 离线成员重连后自动补发缺失消息（基于 seq_num）

### 6.3 Session 归档（可选）

```
Session owner 开启归档（动态切换）
  → session 内出现"归档"按钮
  → Session owner 选择消息片段 → 触发归档
  → 走标准归档流程（AI 分析 → 推荐图谱操作 → 确认 → Git commit/PR）
  → 归档结果写入 Ring 的知识图谱
```

### 6.4 Session 生命周期

```
创建 Session
  → 活跃讨论（active）
  → Session owner 关闭 Session（closed）
     → 聊天记录保留在创建者后端 SQLite
     → Session owner 可随时重新打开
  → 或 Session owner 删除 Session（deleted）
     → 所有记录清除，不可恢复
```

### 6.5 成员离线处理

```
成员网络中断
  → 创建者后端继续缓存该 session 的消息
  → 成员重连
  → 客户端发送最后收到的 seq_num
  → 创建者后端返回 seq_num 之后的所有消息
  → 成员看到完整的离线期间讨论
```

### 6.6 Session owner 离线处理

```
Session owner 离线
  → 创建者后端推送 session_paused 事件给所有参与者
  → 所有参与者无法发消息（Session 暂停）
  → Session owner 重连
  → 创建者后端推送 session_resumed 事件
  → 所有参与者可继续发消息
```

## 7. 导出流程

### 7.1 导出图谱图片

```
用户在图谱视图中点击"导出"按钮
  → 选择格式（PNG / SVG / PDF）
  → 前端通过 D3.js 渲染静态快照
  → 下载文件
```

### 7.2 导出 Markdown / 对话 / Session 记录

```
用户在对应视图中点击"导出"
  → 选择格式（Markdown / PDF）
  → 后端生成文件
  → 下载
```

### 7.3 生成 AI 结构化报告

```
用户选择一个或多个图谱节点
  → 点击"生成报告"
  → 填写报告主题
  → Group Ring 基于节点内容生成结构化报告
  → 用户预览 → 选择导出格式（Markdown / PDF）
```

### 7.4 整 Ring 数据备份

```
用户在 Ring 设置中点击"备份数据"
  → 后端打包 graph.json + Markdown + 元数据 + assets
  → 生成 .tar.gz 文件
  → 下载
```

## 8. 图谱修正流程

```
场景：Group Ring 创建了错误的节点/边，或归档了不该归档的内容

修正方式（二选一）：

1. 对话中指示 Group Ring
   → 用户说"删除刚才那个节点" 或 "把节点 A 的内容改一下"
   → Group Ring 执行修正
   → 变更生成 Git commit/PR

2. Git 回滚
   → 在归档视图的提交历史中找到错误 commit
   → 执行 revert
   → 图谱恢复到之前的状态
```

> **图谱可视化**：支持展开/折叠节点（查看或隐藏子节点），支持缩放、平移、高亮。不支持在可视化界面上直接编辑。
