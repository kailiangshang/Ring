## 1. 四层 AI 架构

Ring 系统包含四个层级的 AI 实例，严格分层，各自独立运行。

### 1.1 Super Ring（Hub 级，全局）

**职责范围**：跨 Ring 的全局事务。

**功能**：
- 帮助创建 Ring（引导填写名称、Group Ring prompt）
- 蓝图构建引导（推荐图谱模板、协助确定顶层分类）
- 跨 Ring 洞察（"你的三个 Ring 都涉及到竞品分析，是否合并？"）
- 新用户引导（首次使用时引导了解 Ring 概念和操作）
- 全局设置管理（LLM 配置、隐私规则）
- 跨 Ring 分析、问答、总结、合并推荐
- Skill 安装（用户一句话安装网络插件）

**入口**：Ring Hub 首页的 Super Ring 入口。

**上下文**：不受 Ring 角色权限限制，可按需只读访问本机所有 Ring 内容（图谱、归档 Markdown）。合并推荐只生成建议，合并操作由用户在具体 Ring 中执行。

### 1.2 Group Ring（Ring 级，群组专属）

**职责范围**：单个 Ring 内的所有事务。

**行为驱动**：`.group/` 持久化文档体系（非单一 system prompt）。6 个 MD 文档存储在 Git 仓库中，随 Ring 一起版本管理和进化。

**功能**：
- 被动响应：成员提问、调用工具、推荐归档
- 主动介入：关键节点自动触发总结或建议
- 蓝图构建：使用特殊蓝图 prompt 引导用户构建图谱
- 自成长：用户行为反馈写入 `.group/` 文档，持续优化行为

**入口**：Ring 空间内的对话视图。

**上下文加载策略**：
- 核心层（始终加载）：`role.md` + `conventions.md` + `active-context.md`
- 扩展层（按需加载）：`archive-patterns.md`（归档时）、`corrections.md`（修正后）、`knowledge-summary.md`（全局理解时）

**自成长机制**：
- 用户修正 AI 行为 → 写入 `corrections.md`
- AI 观察到归档模式 → 写入 `archive-patterns.md`
- 定期总结 Ring 知识 → 更新 `knowledge-summary.md`
- 每次对话维护当前上下文 → 更新 `active-context.md`
- 用户可编辑 `role.md` 和 `conventions.md` 调整 AI 行为

### 1.3 Session Ring（Session 级，讨论场景）

**职责范围**：多人讨论会话内的 AI 协助。

**功能**：
- 基于 Skill 提供定向能力（Skill 决定行为）
- 材料准备（必需）：AI 基于描述收集/生成材料
- 所有 session 成员共享，回复广播

**入口**：Session 创建时自动激活。

**上下文**：继承 Group Ring 的 prompt 和数据（只读图谱 + 归档）+ Skill。

**生命周期**：Session 关闭后实例销毁。

### 1.4 Self（独立层，用户私有 AI 宠物）

**职责范围**：用户私有的信息收集和行为统计。

**功能**：
- 信息收集
- 行为统计（Session 参与、工具调用、屏幕停留时长、归档行为）
- 给用户提建议
- 用户在时作为助手

**入口**：通过 Super Ring 入口访问。

**数据存储**：`~/.ring/self/`（完全私有，不进 Git）。

**权限边界**：
- 完全私有，不进 Git
- 不被邀请到其他 Group
- 不参与 Session
- 不替代用户发言

## 2. Group Ring 行为模式

### 2.1 被动响应（日常对话模式）

**触发条件**：用户在对话中提问或请求。

**行为**：
- 查询 Ring 的图谱和归档内容，回答问题
- 调用原子工具（文件解析、全文搜索、网页爬取等）
- 工具产出后，可主动推荐"是否归档到图谱"（但不强制）

**限制**：
- 不能修改图谱
- 不能执行 Git 操作
- 不能创建或修改 Markdown 文件

### 2.2 推荐归档（手动归档模式）

**触发条件**：
- 用户说"归档"/"保存"/"记录到图谱"
- 用户点击 export 按钮
- 工具产出后 AI 主动推荐

**行为**：
1. 分析待归档内容，识别关键信息
2. 匹配蓝图中的图谱大类
3. 推荐图谱操作：
   - 创建新节点（建议名称和所属图谱大类）
   - 挂载到现有节点
   - 创建新的边（关系）
4. 展示推荐预览
5. 等待用户确认
6. 执行：生成 Markdown 文件 + 更新 graph.json + Git 操作

**判断标准**：
- 内容包含决策、结论、知识点、行动项等有价值信息
- 不归档纯闲聊或问候

### 2.3 自主归档（Auto 模式）

**触发条件**：用户点击"Auto"按钮进入。

**行为**：
- 持续监控对话和工具产出
- 基于 LLM 语义判断内容是否值得归档（包含决策/结论/知识点）
- 自动执行：创建/更新节点 → 生成 Markdown → Git commit
- 不需要用户逐个确认

**边界**：
- 闲聊不归档
- 上传文件自动归档
- 对话基于语义判断
- 误归档可修正（图谱编辑、对话修正、Git 回滚）

## 3. Session Ring 行为模式

### 3.1 Session 生命周期

1. **创建 Session**
   - 选择场景类型（加载对应 Skill）
   - 填写标题和描述
   - 邀请成员

2. **材料准备**（必需）
   - AI 基于描述收集/生成材料
   - 参与者可查看进度
   - 创建者可标记重点

3. **讨论阶段**
   - 所有成员参与讨论
   - AI 加载对应 Skill 决定行为

4. **总结**（可选）
   - 可配置 auto 或 manual
   - AI 生成总结
   - 用户确认后执行后续操作

5. **结束**
   - 结束信号必须由 owner 发起
   - 聊天记录保留在创建者后端
   - 可随时重新打开

### 3.2 Skill 驱动

Session Ring 的行为由 Skill 决定：
- Session 创建时选择 Skill 或 AI 自动判断
- Skill 互斥，一次只加载一个
- 预设 Skill：`meeting_archive`、`deep_research`、`learning_center`

## 4. 主动触发规则

Group Ring 在以下关键节点主动介入：

### 4.1 归档推荐

**触发**：有新内容产生（对话片段、工具产出、文件上传）后。

**行为**：
- 分析内容是否包含值得归档的信息
- 如果是，推荐归档操作（手动模式下）或自动归档（Auto 模式下）
- 如果否，不干预

### 4.2 图谱节点推荐

**触发**：内容标记归档时。

**行为**：
- 分析内容属于蓝图中哪个图谱的哪个大类
- 推荐创建新节点或归入现有节点
- 如果内容涉及多个图谱，推荐跨图谱挂载

### 4.3 PR 提醒

**触发**：有新的 PR/MR 提交。

**行为**：
- 通知创建者："@张三 提交了一个归档请求，涉及 1 个新节点和 2 处内容修改"
- 摘要展示 PR 内容

### 4.4 图谱总结

**触发**：图谱新增 N 个节点后（N 可配置，默认 10）。

**行为**：
- 主动总结 Ring 的知识全貌
- 生成一段总结文字展示在对话中
- 示例："你的 Ring 已经有 15 个知识节点。主要集中在【产品分析】和【用户研究】两个方向。最近的讨论热点是 XXX。"

### 4.5 空图谱引导

**触发**：Ring 创建完成、蓝图确认后。

**行为**：
- 引导用户建立第一批实际内容
- "图谱蓝图已建好，你可以上传一份文档或开始讨论，我会帮你逐步填充内容"

## 5. 蓝图构建行为

### 5.1 蓝图阶段特殊 prompt

蓝图构建阶段，Group Ring 的 system prompt 由两部分叠加：

1. **蓝图构建指令**（通用蓝图构建行为）
2. **role.md**（用户设定的角色描述，如"你是一个产品分析专家"）

```
System prompt（蓝图阶段）=
  蓝图构建指令（你是一个知识图谱架构师...）
  + role.md（你是一个产品分析专家...）
```

叠加的好处：Group Ring 既知道怎么引导用户构建蓝图，又知道这个 Ring 的业务场景，能给出更贴切的蓝图建议。

蓝图构建指令的核心目标是**反复拷打用户**，确保蓝图结构真正符合需求：

```
你是一个知识图谱架构师。你的任务是通过反复提问，帮助用户设计出最适合的知识图谱蓝图。
你必须：
1. 从用户的 Ring 名称和描述出发，追问核心使用场景
2. 推荐图谱维度并解释理由，等用户确认
3. 对用户的每个选择追问"为什么？"和"你确定吗？"
4. 如果用户的回答模糊，用具体例子帮助明确
5. 每次调整后重新展示完整蓝图预览
6. 只有在用户明确确认后才结束蓝图构建
你不允许：
1. 一次性给出完整方案不经过确认
2. 跳过追问直接建立
3. 在用户未明确确认时结束
```

蓝图确认后，去掉蓝图构建指令，只保留 role.md + 其他 .group/ 文档进入日常模式。

### 5.2 蓝图构建入口（两条路径）

**快速路径**：
1. 用户在蓝图构建页面浏览预设模板卡片
2. 点击模板卡片 → 预览图谱结构（D3.js 可视化，节点+边）
3. 点击"使用此模板" → 确认蓝图 → 建立

**深度路径**：
1. 用户点击"自定义"或"从零开始"
2. Group Ring 使用蓝图 prompt + role.md 启动蓝图构建对话
3. 通过不限轮数的对话，和用户反复确认：
   - "这个 Ring 主要用来做什么？"
   - "我建议创建以下图谱维度：【知识图谱】、【事件图谱】、【人物图谱】，你觉得合适吗？"
   - "知识图谱下，我建议初始分类为：概念、方法、工具。你觉得需要调整吗？"
3. 每次调整后展示可视化预览
4. 用户点击"确认蓝图"后建立图谱

### 5.3 蓝图模板预设

系统预设模板供用户选择或定制：

| 模板名 | 图谱组成 |
|--------|---------|
| 产品研究 | 知识图谱、竞品图谱、事件图谱 |
| 项目管理 | 任务图谱、决策图谱、人物图谱 |
| 学习笔记 | 知识图谱、概念图谱 |
| 技术文档 | 架构图谱、API 图谱、变更图谱 |
| 空白 | 无预设，完全自定义 |

## 6. 错误处理

### 6.1 AI 判断错误

当 AI 归档了不该归档的内容或创建了不合理的节点：

- 用户可在对话中指示 Group Ring 修正（"删除刚才那个节点"）
- 用户可在归档视图的 Git 历史中 revert

### 6.2 AI 无法理解

当 AI 无法理解用户意图时：
- 明确说明不理解的部分
- 提供选项让用户选择
- 不猜测，不盲目执行

### 6.3 工具调用失败

当原子工具调用失败时：
- 向用户报告错误原因
- 提供重试选项
- 不静默忽略
